\subsection*{The three phases}

The prologue issues loads for tile 0 into \co@lf0@ and \co@rf0@. No previous tile exists to compute on yet, so these first transfers establish the state needed by the loop.

In steady state, the loop issues the next loads into \co@lf1@ and \co@rf1@, waits for the current loads, and computes from \co@lf0@ and \co@rf0@. The two pairs refer to different buffers, so the next transfer can overlap the current computation. The next loads need not finish first. After the current computation, \co@swap@ makes the next pair current for the following iteration.

The epilogue consumes the final loaded tile after the loop has stopped issuing transfers. It still requires that tile's load to be complete before reading it. The listing above illustrates handle rotation but omits a final wait and output initialization; a runnable accumulation must supply both, just as it does for the steady-state reads.
