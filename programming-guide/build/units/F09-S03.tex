\subsection*{Swizzle and layout conflicts}

A swizzle changes how elements of a staged tile are arranged in shared storage. The logical matrix shape stays the same, but the reader must use the matching address mapping. Croqtile exposes this choice on the copy operation:

\begin{lstlisting}[language=croqtile,caption={A swizzled copy}]
dma.copy.swiz<128> src => dst;
\end{lstlisting}

The MMA read path must use the same \texttt{swiz\textless{}N\textgreater{}} so addresses match the staged layout:

\begin{lstlisting}[language=croqtile,caption={A swizzled mma load}]
ma = mma.load.swiz<128> lhs_load_s.chunkat(_, iv_warp);
\end{lstlisting}

Swizzle is a property of the copy, not of a particular engine: \texttt{dma.\allowbreak{}copy.\allowbreak{}swiz\textless{}N\textgreater{}} produces the same shared-memory layout regardless of how the data gets there.

\textbf{Swizzle width.} The template argument is the swizzle width in bytes, and the examples use \texttt{swiz\textless{}128\textgreater{}}. A wider swizzle defeats wider conflict patterns but requires tile extents that line up with that width.

\textbf{Matching rule.} The \texttt{\textless{}N\textgreater{}} on the copy must match \texttt{mma.\allowbreak{}load.\allowbreak{}swiz\textless{}N\textgreater{}}. If you load with plain \texttt{mma.load} from \texttt{swiz\textless{}128\textgreater{}} data, addresses disagree and you read garbage. The compiler does not enforce the pairing --- it is a correctness invariant you maintain. (As introduced in Section~\ref{sec:3-7}, \texttt{mma.\allowbreak{}load.\allowbreak{}swiz\textless{}N\textgreater{}} is part of the MMA load family.)
