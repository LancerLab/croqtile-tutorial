\subsection*{DMA vs TMA}

DMA and TMA use similar source and destination expressions, but their implementations impose different constraints. The DMA path uses cooperating threads to move the tile. TMA describes a tensor transfer to an engine through a descriptor, so the compiler must be able to construct that description before the kernel uses it.

\begin{table}[htbp]
\centering\small
\begin{tabularx}{\linewidth}{@{}lXX@{}}
\toprule
 & \textbf{\texttt{dma}} & \textbf{\texttt{tma}} \\
\midrule
Common destination & \texttt{shared} & \texttt{shared} \\
Async support & Yes & Yes \\
\bottomrule
\end{tabularx}
\end{table}

Example TMA use:

\begin{lstlisting}[language=croqtile,caption={DMA vs TMA}]
f = tma.copy.async lhs.subspan(64, 64).at(block_m, iv_k) => shared;
wait f;
\end{lstlisting}

The practical rule is simple:

\begin{itemize}[leftmargin=1.6em]
\item Use \texttt{dma} when tile sizes are dynamic, irregular, or you want the portable path.
\end{itemize}
