\subsection*{\textbf{b. Type Safety and Compile-Time Checking}}

One of the major benefits of symbolic dimensions in Croqtile is that they are \textbf{type-safe} and \textbf{checked at compile-time}. Croqtile allows you to declare symbolic dimensions and even manipulate them algebraically (e.g., \texttt{M / 2}, \texttt{N / 4}), ensuring that they adhere to the expected types and constraints. This eliminates the need for runtime checks, which can often lead to errors or performance penalties.

For example, using \texttt{?} or \texttt{-1} as dynamic dimensions in other systems often leads to runtime checks for consistency, such as verifying that the dimensions are properly initialized before use. These checks can introduce overhead and make the program harder to optimize. In contrast, symbolic dimensions allow Croqtile to \textbf{check constraints at compile-time}, ensuring that shape expressions are valid before execution:

\begin{lstlisting}[language=croqtile,caption={b. Type Safety and Compile-Time Checking}]
mdspan sp : [M, N];
// M and N are symbolic dimensions
mdspan spn : sp [1, M / 2, N / 4];
// Compiler ensures validity of shape expressions`
\end{lstlisting}

This ensures type consistency and reduces the potential for errors during runtime.
