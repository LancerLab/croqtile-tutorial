\subsection*{\textbf{b. Type Safety and Compile-Time Checking}}

Symbolic dimensions let the compiler reason about expressions without knowing every numerical extent. It can check ranks and simplify relationships such as repeated uses of \co@M / 2@. This does not eliminate runtime validation: whether caller-supplied dimensions agree or satisfy a required constraint may only be known when the function is entered.

The expression below keeps the derived shape tied to the named input dimensions. That connection is available to the compiler and visible to the reader, instead of being maintained through separate size arguments:

\begin{lstlisting}[language=croqtile,caption={b. Type Safety and Compile-Time Checking}]
mdspan sp : [M, N];
// M and N are symbolic dimensions
mdspan spn : sp [1, M / 2, N / 4];
// Compiler ensures validity of shape expressions`
\end{lstlisting}

This ensures type consistency and reduces the potential for errors during runtime.
