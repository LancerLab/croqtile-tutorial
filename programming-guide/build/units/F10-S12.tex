A benchmark kernel looks dense until you know the order in which its parts appear. Read it top down. The file opens with macros and \texttt{\#error} guards that fix the conditions the rest of it is compiled under. Below them sit \texttt{\_\_device\_\_} functions --- helper algorithms such as top-K, reductions and shuffle wrappers that Croqtile passes through unchanged. Then comes the host setup, ordinary C++ that creates buffers, chooses the launch configuration and takes timings. The centre of the file is the \texttt{\_\_co\_\_} function, where the orchestration lives: \texttt{parallel}, \texttt{foreach}, TMA/MMA, \texttt{inthreads.async} and events, each region mapping back to one of the chapters you have just read. Last are the \texttt{\_\_cpp\_\_} islands, usually only a handful of lines. Most production files follow this order, so the same five checks work every time.
