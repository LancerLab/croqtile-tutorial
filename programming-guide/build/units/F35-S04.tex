\subsection*{Deadlocks}

Events are lock-free by default to support efficient synchronization between asynchronous blocks. Multiple instances updating the same event require care, particularly when using \texttt{wait}.

For example,

\begin{lstlisting}[language=croqtile,caption={A single-instance deadlock}]
parallel p by 1 {
  shared event e;
  trigger e;   // one thread set e;
  parallel q by 2 {
    wait e;    // two threads can reset e;
  }
}
\end{lstlisting}

Both threads wait on the same event \texttt{e}. Because \texttt{wait} resets the event, \texttt{thread-0} may reset it before \texttt{thread-1} observes the trigger. In that case, \texttt{thread-1} remains blocked and the program deadlocks.

\begin{lstlisting}[language=croqtile,caption={One trigger per waiter}]
qc = 2;
parallel p by 1 {
  shared event e[qc];
  trigger e;   // one thread set e[0] and e[1];
  parallel q by qc {
    wait e[q]; // no dead lock
  }
}
\end{lstlisting}

In this code, you utilize an event array to guarantee each event is waited and reset by a single thread.
